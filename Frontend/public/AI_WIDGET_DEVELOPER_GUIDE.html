1. Executive Overview & Core Purpose Omnichannel Compliance Intelligence

1. Executive Overview & Core Purpose

1.1 What is the Embeddable Floating AI Widget?

The Embeddable Floating AI Compliance Widget (ComplianceWidget.jsx) is a self-contained, lightweight, interactive chat assistant designed to float in the bottom-right corner of any web application. It provides users with immediate, context-aware answers to UK financial regulatory questions (FCA, PRA, Bank of England) without redirecting them away from their active workflow or forcing them to create an account.

1.2 Enterprise Banking & Intranet Use Cases

In modern financial institutions, regulatory compliance is not confined to a single back-office portal. Compliance inquiries occur across diverse operational touchpoints:

  • Internal Banking Intranets: Loan officers, trading desk personnel, and relationship managers can verify regulatory clauses (e.g. Consumer Duty PRIN 2A or CASS 7 Client Money segregation) while reviewing client agreements.
  • Customer-Facing Banking Portals: Retail and corporate banking customers can access plain-English explanations of statutory rights, complaint timelines (DISP 1.6), and dispute mechanisms.
  • Third-Party Partner Websites: Independent mortgage brokers, financial advisers, and fintech partners can embed the firm's compliance intelligence via a simple <iframe> without any codebase dependencies.
  • Guest User Onboarding: Prospective clients and unauthenticated visitors can test the assistant with zero login friction.

1.3 Single AI Brain, Multiple Frontends Principle

The floating widget is not an independent or stripped-down AI model. It is a client-side presentation layer that connects directly to the centralized UK Finance AI Compliance Engine. Both the full-screen desktop dashboard (/chat) and the floating widget share:

  • The same 4-Tier Caching System (L1 RAM, L2 MongoDB, L3 Qdrant Semantic Cache, L4 Regex History).
  • The same Qdrant Vector Database containing auto-indexed FCA/PRA rule chunks.
  • The same Sub-Second Groq LLM Inference (openai/gpt-oss-120b on LPU hardware).
  • The same AI Gatekeeper & Master System Prompt guardrails.

3.2 The 8-Stage Inquiry Lifecycle

  1. Launcher Activation: The user clicks the floating button. The widget activates an overlay backdrop (rgba(12, 22, 20, 0.58) with blur(3.5px)) and sets document.body.style.overflow = 'hidden'.
  2. Session Identification: The component fetches uk_finance_widget_session_id from localStorage or generates a unique wgt_... UUID.
  3. Payload Dispatch: Dispatches POST /api/agent/query with { question, widgetSessionId, isWidget: true }.
  4. Thread Matching: MongoDB retrieves the ongoing session thread using widgetSessionId to provide multi-turn conversation memory.
  5. Multi-Tier Cache Interception: Checks L1 RAM Map (<1ms), L2 MongoDB (<5ms), and L3 Qdrant Semantic Cache (~18ms). If a semantic match (≥ 80%) exists, the system returns the pre-saved answer at 0 token cost.
  6. RAG Vector Retrieval (Cache Miss): Local BGE embeddings convert the query into a 384-dimensional vector, pulling the top 4 relevant clauses from Qdrant.
  7. Small-Screen LLM Formatting: Groq LLM synthesizes the answer, enforcing 3 to 5 concise bullet points with bold rule codes (e.g. DISP 1.6.2 R) and suppressing wide tables.
  8. Client Rendering: The widget parses Markdown via react-markdown + remark-gfm, rendering interactive citation badges and clickable follow-up chips.
4. Strategic Trade-offs Advantages & Considerations

4. Advantages, Disadvantages & Strategic Trade-offs

4.1 Key Strategic Advantages

  • Zero User Friction: Users get instant regulatory compliance advice without logging in, creating accounts, or navigating away from their current task.
  • 100% Centralized AI Brain: Embedded websites do not need to host AI models or maintain vector stores. All intelligence runs on the centralized backend.
  • Full Caching Economics: Enjoys the exact same 4-tier caching benefits as the desktop application. Repeated or paraphrased questions return in 18ms at 0 token cost.
  • Intelligent Small-Screen Formatting: Eliminates table overflow by automatically summarizing multi-column comparisons into 3–5 compact bullets.
  • Persistent Multi-Turn Memory: Users can ask natural follow-up questions ("What must they do if it expires?") without losing conversational context.
  • Universal Drop-in Integration: Integrates into React applications as a drop-in component, or into WordPress, Webflow, and custom HTML via a standard <iframe> or 1-line script.

4.2 Engineering Limitations & Trade-offs

Limitation Impact on User Experience Architectural Reason
Screen Real Estate Cannot comfortably render 10-column tables or multi-page documents. The popup is constrained to 380px–400px width to avoid obstructing mobile screens.
Client-Side Session Scope Clearing browser cookies/cache resets the conversational thread. Guest sessions rely on localStorage UUIDs rather than persistent database user accounts.
Cross-Origin Restrictions Iframes require explicit CORS headers and sandbox permissions. Web browsers enforce strict cross-origin policies for embedded iframes.
No Admin Controls Document uploads and user management cannot be performed from the widget. The widget is intentionally locked to EMPLOYEE / GUEST query capabilities for security.

4.3 Production Mitigation Strategies

  • Table Request Override: If the user explicitly asks for a table ("Show me a comparison table..."), the backend detects the keyword and renders a compact Markdown table.
  • Session Reset Button: An integrated reset button (RotateCcw) allows users to wipe their widgetSessionId and start a clean thread at any time.
  • Permissive CORS Configuration: The Express backend uses cors({ origin: true, credentials: true }) to allow seamless embedding on partner banking domains.
5. Backend Architecture API & Route Implementation

5. Backend Engine & API Architecture

5.1 Optional Authentication Gateway (optionalAuthenticate)

In backend/src/routes/agent.routes.js, the query route is guarded by an optional authentication middleware:

// Accepts requests with OR without a Bearer JWT token
router.post('/query', optionalAuthenticate, askAgent);
router.get('/widget/session/:widgetSessionId', getWidgetSession);
router.delete('/widget/session/:widgetSessionId', clearWidgetSession);

If an Authorization header is present, the request is linked to the authenticated user's profile. If omitted, the request is treated as a guest and linked to widgetSessionId.

5.2 Session Persistence via widgetSessionId

In backend/src/controllers/agent.controller.js, the server inspects the incoming body:

let conversation = null;
if (widgetSessionId) {
  conversation = await Conversation.findOne({ widgetSessionId, isArchived: false });
  if (!conversation) {
    conversation = await Conversation.create({
      widgetSessionId,
      source: 'WIDGET',
      title: question.slice(0, 40),
      messages: []
    });
  }
}

This enables anonymous users to have full multi-turn pronoun memory ("What are their obligations under that rule?") across repeated inquiries.

5.3 Smart Table Suppression & Adaptive Output Engine

In backend/src/services/ragAgent.service.js, the system prompt dynamically adapts based on the isWidget flag:

const askedForTable = /\b(table|tabular|columns|grid|matrix)\b/i.test(question);

const formattingRule = isWidget
  ? askedForTable
    ? '6. WIDGET TABLE MODE: User explicitly requested a table. Present distinctions in a compact Markdown table.'
    : '6. WIDGET CONCISE MODE: Keep answer concise (3 to 5 short bullets, ~90–150 words total). DO NOT output Markdown tables.'
  : '6. Standard Chat: When comparing rules, present key distinctions in a clean Markdown table.';
6. Frontend Implementation UX Design & Lifecycle

6. Frontend Implementation & UX Design System

6.1 Client Session UUID Lifecycle (localStorage)

A unique session identifier is generated once and stored in the browser's localStorage. This ensures that navigating across multiple pages on the host website does not wipe the user's ongoing conversation:

const getOrCreateWidgetSessionId = () => {
  let sessionId = localStorage.getItem('uk_finance_widget_session_id');
  if (!sessionId || sessionId.length < 8) {
    sessionId = 'wgt_' + Date.now().toString(36) + '_' + Math.random().toString(36).substring(2, 9);
    localStorage.setItem('uk_finance_widget_session_id', sessionId);
  }
  return sessionId;
};

6.2 Backdrop Dimming & Body Scroll Lock Mechanics

To focus user attention on regulatory advice and prevent disorienting double-scrolling, the widget applies an overlay backdrop and freezes host page scrolling while open:

useEffect(() => {
  if (isOpen) {
    const original = document.body.style.overflow;
    document.body.style.overflow = 'hidden';
    return () => { document.body.style.overflow = original; };
  }
}, [isOpen]);

6.3 Dual-Mode Architecture (floating vs. iframe)

The component supports two rendering modes via props:

  • mode="floating": Renders the launcher button, blurred backdrop overlay, and popup window.
  • mode="iframe": Renders only the chat card filling 100vw / 100vh for embedding inside an <iframe>.
// Pinned floating container
<Box position="fixed" bottom="24px" right="24px" zIndex={9999}>
  {isOpen && (
    <Box w={{ base: '340px', sm: '400px' }} h="590px" mb={3} borderRadius="20px">
      {renderChatCard()}
    </Box>
  )}
  <Button onClick={() => setIsOpen(!isOpen)}>
    {isOpen ? 'Close Assistant' : 'Ask UK Compliance AI'}
  </Button>
</Box>

Phase 1: Backend API Gateway

Create a POST /query endpoint that accepts { question, widgetSessionId, isWidget }. Use optional authentication so public guests can query immediately. Enable CORS headers (origin: true) for cross-domain requests.

Phase 2: Client Session & Memory

On the client, generate a persistent UUID (wgt_...) in localStorage. In the backend, query the Conversation collection using widgetSessionId so the model remembers pronouns across turns.

Phase 3: Fixed Floating Layout

Pin the launcher button using CSS position: fixed; bottom: 24px; right: 24px; z-index: 9999. Add a backdrop overlay at z-index: 9998 with background: rgba(12, 22, 20, 0.58) and lock background scroll via document.body.style.overflow = 'hidden'.

Phase 4: Small-Screen Formatting

Instruct the LLM in your system prompt: "When isWidget is true, format responses into 3 to 5 concise bullet points (~90–150 words) with inline bold citations. Do not output Markdown tables unless explicitly asked."
