1. Executive Summary & Problem Overview Regulatory Grounding

1. Executive Summary & Problem Overview

1.1 The Business & Regulatory Challenge

Financial institutions operating in the United Kingdom face one of the world's most intricate and actively enforced regulatory environments, overseen by the Financial Conduct Authority (FCA) and the Prudential Regulation Authority (PRA).

  • Volume & Complexity: The official FCA Handbook contains tens of thousands of clauses across dozens of specialized sourcebooks (PRIN, Consumer Duty / PRIN 2A, CASS 7, SYSC 4, DISP 1.6, PROD 4, SUP, FIT, COBS).
  • Severe Non-Compliance Penalties: Breaching statutory provisions (such as client money segregation under CASS 7 or complaint timeframes under DISP 1.6) exposes firms to multimillion-pound fines, public censure, and loss of regulatory permissions.
  • Hallucination Risk of Public LLMs: Standard generic commercial AI models (such as vanilla ChatGPT) frequently hallucinate regulatory clauses, confuse US rules (SEC/FINRA) with UK rules (FCA/PRA), or cite outdated provisions.
  • Cost & Latency Bottlenecks: Full RAG prompts with regulatory text consume 1,500 to 3,500 tokens per inquiry, leading to substantial recurring API costs and 15–20 second response times.

1.2 The Solution: Grounded Regulatory Intelligence

The UK Financial Rules AI Compliance Assistant is an enterprise-grade, retrieval-augmented intelligence system designed to solve these challenges:

  1. 100% Grounded in Official Corpus: Every answer is synthesized exclusively from official regulatory PDFs/DOCXs uploaded and indexed into the firm's vector database.
  2. Multi-Sourcebook Cross-Synthesis: Automatically synthesizes cross-cutting rules when an inquiry touches multiple regimes (e.g. PROD 4 Product Governance + PRIN 2A Consumer Duty).
  3. Multi-Tier Caching: Cuts API token costs and reduces query latency from 18 seconds to 18 milliseconds on repeated and semantically similar queries.
  4. Omnichannel Access: Operates as a full desktop compliance portal (/chat) and as an isolated, embeddable floating widget (/widget, /test) that can be dropped into any banking intranet or customer portal.

2.3 Vector Database, Local Embeddings & Rule Chunks

Vector Database Qdrant Vector Engine running on port 6333 in Docker. Manages regulatory_rules (auto-indexed rule passages) and semantic_cache (query vectors) with Cosine distance metric.
Local Embeddings Model Xenova/bge-small-en-v1.5 executed locally via @huggingface/transformers. Generates fast 384-dimensional dense vectors with zero external embedding API fees or network lag.
Regulatory Rule Chunks Official UK regulatory handbooks (thousands of pages) are automatically parsed and sliced into cohesive semantic sections (~500–800 chars each) tagged with authority (FCA/PRA), sourcebook, and exact rule codes. Automatically scales as new documents are ingested.

2.4 LLM Inference Engine & Document Pipeline Packages

LLM Inference Engine Groq Cloud API (groq-sdk v1.6) executing openai/gpt-oss-120b / Llama-3-70B. Powered by specialized LPU (Language Processing Unit) hardware delivering sub-second response times (<1000ms) with temperature set to 0.1 for strict compliance grounding.
Document Parsers pdf-parse (extracts text, sections & statutory headings from official FCA PDFs) and mammoth (extracts raw text from Word .docx compliance manuals).
Text Chunking Engine @langchain/textsplitters (implements recursive character text splitting preserving regulatory section hierarchies).

3.2 Lifecycle of a Compliance Inquiry

  1. User Submits Question: The user submits an inquiry via the main chat interface or floating widget (e.g. "What are the complaint time limits under FCA DISP?").
  2. Pronoun & Context Resolution: If the question contains pronouns ("What must they send to them if it is not resolved?"), the backend resolves references against prior turns.
  3. Multi-Tier Cache Inspection: Checked against L1 RAM, L2 MongoDB, and L3 Qdrant Semantic Vector Cache. If a match is found (≥80% similarity), the response returns in 18ms with 0 tokens consumed.
  4. Vector Search (Cache Miss): Local BGE embeddings convert the query into a 384-dimensional vector, retrieving the top 4 most relevant clauses from Qdrant.
  5. Guardrail Validation: Out-of-scope inquiries (cooking, sports, general coding) trigger a strict refusal with NOT_FOUND confidence.
  6. LLM Synthesis: Groq LLM synthesizes the answer, citing exact rule codes (e.g. DISP 1.6.2 R).
  7. Adaptive Formatting: If isWidget: true, the answer is converted into 3–5 compact bullets; if normal chat, full comparison tables are rendered.
  8. Persistence & Ingestion: The turn is saved to MongoDB and indexed into the semantic cache for future instant hits.
4. Prompt & Semantic Caching Token & Cost Economics

4. Prompt & Semantic Caching (Token & Cost Optimization)

4.1 Why Caching is Critical in Regulatory RAG

In an enterprise financial firm, employees and clients frequently ask identical or slightly rephrased compliance questions. Without caching, every single inquiry sends ~1,500–2,500 prompt tokens to the LLM. Multi-tier caching intercepts these queries, dropping input tokens to zero and latency from 18 seconds to 18 milliseconds.

4.2 How the Multi-Tier Cache Works (All Levels Explained)

5. Role-Based Access Control Permissions Matrix

5. Role-Based Access Control (RBAC) & Feature Breakdown

The platform enforces strict role-based access control across all frontend views and backend REST endpoints.

  • Anonymous / Guest Visitors: Can open and chat with the floating widget on /widget and external sites (/test). Allowed 2 preview questions in /chat before login is required.
  • Compliance Employee (EMPLOYEE): Unlimited interactive compliance chat, multi-turn pronoun memory, verified rule citations with confidence scores, personal chat history management. Blocked from administrative controls.
  • Compliance Administrator (ADMIN): Everything an employee can do, plus regulatory document ingestion (PDF/DOCX), Qdrant rules library management, team management (provisioning users, promoting/demoting roles), and token & cost analytics.

6. Embeddable Floating Widget Omnichannel Integration

6. Embeddable Floating AI Compliance Widget

6.1 Core Concept & UX Principles

The Compliance Widget (ComplianceWidget.jsx) allows any external banking portal, intranet, or client website to embed the AI compliance assistant seamlessly:

  • Fixed Corner Launcher: Pinned to bottom-right corner (position: fixed; bottom: 24px; right: 24px; z-index: 9999).
  • Page Backdrop Dimming: A blurred backdrop overlay (rgba(12, 22, 20, 0.58) + backdropFilter: blur(3.5px)) dims the host website, focusing attention on compliance advice.
  • Background Scroll Lock: Disables host page scrolling (document.body.style.overflow = 'hidden') while open so wheel scrolling stays inside the chat card.

6.2 Smart Table Suppression & Mobile Formatting

Standard desktop chat generates wide, 4-column Markdown comparison tables. Inside a 380px floating popup, wide tables cause horizontal overflow. The backend automatically detects isWidget: true and converts wide tables into 3 to 5 concise bullet points with bold inline rule codes. If the user explicitly asks for a table ("Show me a comparison table..."), the widget honors the request and renders a structured Markdown table.

7.2 The 7 Mandatory Compliance Guardrails

  1. Corpus Grounding: Prohibits generic AI speculation; answers must originate from the vector database.
  2. Out-of-Scope Refusal: Questions on non-compliance topics (sports, cooking, general coding) are refused with NOT_FOUND confidence.
  3. Cross-Sourcebook Synthesis: Synthesizes multiple regulatory regimes when a question bridges multiple topics (e.g., Consumer Duty + Dispute Resolution).
  4. Statutory Citations: Requires explicit citation of rule codes (PRIN 2A.2.27 R, CASS 7.15, SYSC 4.1.1 R).
  5. Grounded Follow-Ups: Prohibits speculative suggested follow-ups; questions must reflect actual indexed clauses.
  6. Adaptive Layout (Widget vs. Chat): Formats concise bullet points for 380px widgets and comprehensive tables for full-screen dashboards.
  7. Pronoun & Anaphora Memory: Resolves relative references across conversational turns while preserving context.

7.3 JSON Structured Output Contract

By enforcing a strict JSON schema contract at temperature 0.1, the backend guarantees deterministic parsing, reliable citation badges, real-time follow-up chips, and predictable UI rendering across all client applications.

8. Gatekeeper, Live Sync & Governance Authenticity & Real-Time Intelligence

8. AI Gatekeeper, Live Regulatory Sync & Token Governance

8.1 AI Gatekeeper (4-Point Stratified Sampling Engine)

Before any uploaded PDF or Word .docx rulebook is sliced and embedded into the Qdrant vector database, it must pass through the automated AI Gatekeeper (aiGatekeeper.service.js) to prevent vector space contamination:

4-Checkpoint Stratified Sampling Architecture Fixed Economy • ~1,250 Tokens
Checkpoint 1 (0% / Start) Document Cover, Title & Statutory Publication Notice (1,200 chars).
Checkpoint 2 (~15% Mark) Application Scope, General Definitions & Applicable Firm Categories (800 chars).
Checkpoint 3 (~50% Mark) Core Substantive Regulatory Standards & Operational Requirements (800 chars).
Checkpoint 4 (~85% Mark) Transitional Provisions, Enforcement Schedules & Regulatory Powers (800 chars).

Fixed Token Cost: Slicing exactly 3,600 characters across 4 mathematical points guarantees that verification consumes only ~1,200–1,355 Groq tokens, whether verifying a 15-page notice or a 1,000-page handbook. If invalid (e.g. general recipes, resumes, US SEC rules), the upload is rejected immediately before indexing.

8.2 FCA Live Statutory Sync & Incremental Clause Diffing

UK regulations undergo continuous statutory revision. The system incorporates real-time regulatory synchronization:

  • Free & Public Official FCA Feed: The UK Financial Conduct Authority operates under UK Open Government transparency requirements and provides an official, public RSS feed (https://www.fca.org.uk/news/rss.xml). This publication feed is 100% free and open to the public without requiring paid API keys, vendor subscriptions, or authentication tokens.
  • Automated Ingestion (fcaSync.service.js): The backend polls this free public feed with a 15-minute in-memory cache to ingest breaking Handbook Notices, Policy Statements, and consultation papers.
  • MD5 Incremental Clause Diffing (applyIncrementalRuleDiff): When a handbook amendment is detected, the engine does not re-embed the entire 500-page document. It computes MD5 hashes of individual statutory clauses, identifies only modified or new paragraphs, and updates only those specific vectors in Qdrant—saving 95% of embedding CPU compute.

8.3 Token & Cost Governance: Document RAG vs. Gatekeeper Tokens

In the administrative ledger (/admin/cost-analysis), two token metrics are tracked separately:

  • Document RAG Volume: The complete text volume of rulebooks (e.g. 631,065 tokens for SUP.pdf) chunked and embedded 100% locally on server CPU via bge-small-en-v1.5 into Qdrant (0 Groq tokens billed).
  • AI Gatekeeper Tokens: The one-time, fixed security check (~1,250 tokens billed to Groq) that authenticates the document before indexing.
